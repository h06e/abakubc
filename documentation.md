# Overall presentation

Abakub© allows to generate abaqus models of the KUBC machine with a high number of paramters from the sample generation to the level of details in the machine hypothesis and load type.

The `src/` directory contains all the scripts and python modules used by Abakub©. The `sample_bank/` directory contains all the generation geometries (geometry files and csv related to the generation) to avoid the generation of the sample sample multiple times. `inp_files/` contains the input files generated by Abakub© with `main_generation.py`. The directory `results/` is the place where output batabase files (odb) have to be place manually from the runnin directory. The file `campagne-1.csv` contain all the parameters to generate and keep updated all the tests.

# First and quick explanation

## Definition of the tests

In a csv place in the root, typically `campagne-1.csv` all the parameters of each test are defined.

- test_id: A unique id which will used for naming files *eg* `1_A`
- sample_name: Specify the name of sample. It can be one of the `src/geometries/` or directly a .sat file placed in `sample_bank/`. *eg* `monolithic` or `honey`
- geo_parameters: All the geometrical parameters defnied in the correct order seperated by / (when needed only) *eg* for honey: `50/2`
- thickness: resign the thickness of the sample *eg* `30`
- trans_rot: resign the translation and rotation of the patern translation along x (mm) / translation along y (mm) / roation (deg). *eg* `10/0/20`.
- corner_cleaner: defines the corner_cleaner type. Possible values: ` ` *empty* (no cutter), `STD` (for standard cut), `ADV_SHEAR` (deep cut to limit compression in corners area during shear test).
- force_clean: Option used to overpass the auto-detection in the corner. The possible values are `True` `False` (also but not recommended `0` and `1`). If True, the cleaner will operate in each corner even if not needed. Recommended to set to `True`.
- mat: Define the material parameter. Young modulus / Poisson ratio. *eg* `2000/0.3`
- free_rotation: Let the free rotation of the cylinders. Possible values: `True` `False`. 
- perfect_panto: Possible values: `True` or `False`. Define the hypothese of modelization of the cylinders. If True, no clearance, no friction, no stiffness are added.
- stiff_panto: Define the stiffness of the cylinder (the name is not well chosen i know). Top and bottom stiffness / Left and right stiffness. *eg* `200.0E3/8333.0`
- friction: Define the friction parameters in the cylinders. Friction factor / mean internal force / std internal force / minimum internal force / maximum internal force. *eg* 0.1/100/1.0/0.0/200.0
- clearance: Define the clearance parameters in the cylinders. Mean clearance / std clearance / minimum clearance / maximum clearance.
- load_1: $\epsilon_{11} / \epsilon_{22} / \gamma{12}$ of the load. *eg* `-2/0/0`
- load_2: ditto (can be empty)
- load_3: ditto (can be empty)
- flag_make_inp: If `True`, will trigger the generation of the inp by `main_generation.py`
- status: can be modified manually but it over written by main_extract.py after the extraction of the data
- comment: free to use by the user.

## Generation of the model(s)

After defining the campagne, run the script `main_generation.py` to launch the generation of the tests with the `flag_make_inp` set to `True`. When a sample is not `root/sample_bank/`, the sample is generation of the modul geometries. All the sample created are saved into the bank : the geometry file and csv file containing the skipped_cylinders. The inp files are also placed into the directory `root/inps_files/` directory.

## Run the simulation.

All the inp files should place into a apropriate folder for the submition of the jobs. `src/runner.py` can be copied and past into this directory. Running it with python will run all the inp file in the same directory and delete all the file with a different extension that `*.py`, `*.inp`, `*.odb`. 

## Extract the data from the odb files.

The odb files should be then placed into the `root/results/` folder and the script `main_extract.py` can be run in the source. It will create a folder for each test (FOR EACH ODB FILE) in the results directory. Theoritically, the odb file is not needed anymore and can be deleted manually.

For each test, there are:
- pictures of the stresses at each step end.
- `COUP.csv` and `PTBC.csv` containing all the displacement and forces of each cylilnder. If `perfect_panto` was set to `True`, `COUP.csv` can be ignored. The stresses, strain and volume field of each area are also extracted at each end step.
